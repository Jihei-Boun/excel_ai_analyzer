## 왜 이 조합인가

### 파일

- 예산/매출 모두 벤치마크 fixture → 정답 고정, 최근 live에서 **budget·sales domain 성공률 100%**.
- UI용 `data/uploads/*예실대비표*.xlsx`도 가능하지만, 시연 안정성은 `budget_basic.xlsx`가 더 낫습니다.
- 예실대비표를 꼭 쓰려면 **오늘 그 파일로 같은 질문 3회** 통과한 뒤에만 교체.

### 질문 문구

- 스크린샷용 `실행예산 대비 집행률이 높은 비목을 알려줘`는 벤치에 없는 자유 문구라 Plan이 흔들릴 수 있음.
- 같은 스토리(비율+순위)를 검증된 `집행률 상위 3개 항목을 알려줘`로 보여줌.
- Sales도 “합계 구하고 + 상위 5개”처럼 한 문장에 두 요구를 넣지 않음 → `매출 상위 5개 상품을 알려줘`만.

## 대본 (그대로 읽어도 됨)

### 1. 시작 — 30초

*(웹 메인 화면)*

> 지금 개발하고 있는 건 Excel 파일을 업로드하고 자연어로 질문하면 데이터를 분석해주는 웹사이트입니다.  
> 기존에는 질문별 규칙에 의존하는 부분이 많았는데, 현재는 LLM이 분석 방법을 계획하고 Python이 검증·계산하는 구조로 개선하고 있습니다.  
> 샘플 파일로 실제 동작을 보여드리겠습니다.

*(여기서 Phase 번호는 말하지 않음)*

### 2. 예산 Excel 업로드 — 1분

*(`budget_basic.xlsx` 업로드 → 미리보기)*

> 파일을 업로드하면 먼저 컬럼과 데이터 타입, 값의 형태 같은 데이터 구조를 파악합니다.  
> 여기 있는 데이터로 자연어 질문을 해보겠습니다.

### 3. 첫 질문 — 기본 분석 — 1~2분

**입력:** `비목별 실행예산 합계를 알려줘`

*(결과 나온 뒤)*

> 이런 단순 집계도 예전처럼 ‘비목별’이라는 키워드를 보고 미리 만들어 둔 groupby 함수를 바로 실행하는 게 아닙니다.  
> 현재는 Planner가 어떤 분석이 필요한지 판단해서 AnalysisPlan을 만들고, Python이 그걸 실행합니다.  
> 지금 보시는 결과가 그 경로로 나온 결과입니다.

**기댓값 (납득용):**

| 비목분류 | 실행예산_합계 |
|----------|---------------|
| 내부인건비 | 15,000,000 |
| 연구활동비 | 4,300,000 |
| 간접비 | 4,000,000 |
| 연구수당 | 3,000,000 |

*(정렬 순서는 엔진에 따라 달라질 수 있음. 합계 네 값이 맞으면 OK.)*

### 4. 두 번째 질문 — 핵심 시연 ⭐ — 2~3분

**입력:** `집행률 상위 3개 항목을 알려줘`

*(결과 나온 뒤 — 지금 UI에 Plan 단계 목록은 안 나옴. 아래 두 곳을 가리킴)*

1. 채팅 문구 **`분석 계획 결과: 3행`**  
   → Planner 경로로 처리됐다는 표시 (PandasAI/규칙 함수가 아님). `3행` = 상위 3개.
2. 바로 아래 **결과 표 3행**  
   → 내부인건비 ~83% / 간접비 50% / 연구활동비 ~49% 처럼 비율·순위가 숫자로 나온 표.

> 이 질문은 단순히 특정 컬럼을 조회하는 게 아니라,  
> 실행예산과 집행금액을 이용해 비율을 계산하고, 비교한 뒤, 순위를 매겨야 합니다.  
>  
> 화면에 ‘분석 계획 결과’라고 나온 게, LLM Planner가 그 과정을 계획하고 Python이 계산했다는 표시입니다.  
> 실제 비율·정렬 숫자는 표에 나온 그대로 Python에서 수행한 결과입니다.  
>  
> 마지막 LLM은 계산을 다시 하는 게 아니라, 검증된 결과를 설명하는 역할만 합니다.

*(한 줄 보강 → 바로 이어서 Before→After 이미지로)*

> 그래서 같은 질문이라도 ‘규칙 함수 호출’이 아니라 ‘계획 → 검증 → 실행’으로 처리된다는 점이 이전과 가장 큰 차이입니다.  
> 내부 구조는 다음 그림으로 이어집니다.

*(참고: Plan의 세부 op — aggregate → ratio → sort → limit — 는 메타에만 있고 UI에는 안 펼쳐짐. 단계는 report-02 이미지로 설명.)*

**기댓값 (비목분류 집계 후 순위 — 최근 live):**

| 순위 | 비목분류 | 집행률 |
|------|----------|--------|
| 1 | 내부인건비 | ~83.3% |
| 2 | 간접비 | 50% |
| 3 | 연구활동비 | ~48.8% |

한 줄: **내부인건비(약 83%) → 간접비(50%) → 연구활동비(약 49%)**

*(세목 단위로 잡히면 순위가 달라질 수 있음. 그때는 표가 “상위 3개 + 집행률 내림차순”이면 스토리는 유지.)*

### 5. Before → After 이미지 — 2분

*(`report-02-architecture-before-after.png`)*

> 방금 보신 동작의 내부 구조를 간단히 보면 이렇습니다.

*(왼쪽 Before)*

> 예전에는 질문에서 키워드를 찾고, 거기에 맞는 Python 분석 함수를 실행하는 부분이 많았습니다.  
> 그러다 보니 예산표에서는 잘 되는데, 다른 종류의 Excel을 넣으면 규칙을 계속 추가해야 하는 문제가 있었습니다.

*(오른쪽 After)*

> 그래서 지금은 데이터를 이해한 뒤 LLM이 AnalysisPlan을 만들고,  
> Validator가 그 계획이 실제 데이터에서 실행 가능한지 확인합니다.  
> 이후 Python Executor가 계산하고, 결과도 다시 검증합니다.  
> 마지막 LLM은 계산이 아니라 설명만 담당합니다.

*(세부 validation rule은 설명하지 않음)*

### 6. Sales 샘플 — 2~3분

*(`sales_basic.xlsx` 업로드)*

> 예산 파일만 보면 ‘결국 예산 분석 프로그램 아닌가?’라고 보실 수 있어서,  
> 다른 도메인 파일도 같은 엔진으로 돌려보겠습니다.

**입력:** `매출 상위 5개 상품을 알려줘`

*(결과 나온 뒤)*

> 같은 분석 엔진에 매출 전용 코드를 따로 추가한 게 아닙니다.  
> 데이터와 질문이 바뀌어도 Planner가 필요한 분석 과정을 구성하도록 만드는 것이 현재 개발 방향입니다.

**기댓값:**

| 순위 | 상품 | 매출 합계 |
|------|------|-----------|
| 1 | 상품A | 225,000 |
| 2 | 상품D | 215,000 |
| 3 | 상품F | 200,000 |
| 4 | 상품C | 180,000 |
| 5 | 상품E | 157,000 |

한 줄: **상품A → D → F → C → E**

### 7. Benchmark 이미지 — 1분

*(`report-03-benchmark-composition.png`)*

> 그런데 예산이랑 매출 파일 몇 개가 잘 된다고 해서 범용적이라고 판단할 수는 없어서, 별도의 Benchmark를 만들었습니다.

> 항상 같은 파일과 질문으로 테스트해서, 이전 버전보다 실제로 좋아졌는지를 숫자로 비교합니다.

### 8. 성능 그래프 — 마무리 — 1~2분

*(`report-04-phase6-vs-phase12.png`)*

> 처음 Benchmark를 만들었던 Phase 6에서는  
> 전체 성공률과 Planner 직접 처리율이 약 45% 정도였습니다.

> 같은 42개 질문으로 계속 테스트하면서 실패 원인을 수정했고,  
> 현재는 전체 성공률 약 87~88%, Planner 직접 처리율 약 90%까지 올라왔습니다.

> 반대로 Planner가 해결하지 못해서 다른 방식으로 넘어가는 fallback은  
> 약 43%에서 4~5%대까지 감소했습니다.

> 여기서 중요한 건, Benchmark 질문별 정답 코드를 추가해서 점수를 올린 게 아니라는 점입니다.  
> Planner의 분석 방법 선택, 연산 조합, 검증과 재시도 같은 **범용적인 부분**을 수정하는 방식으로 개선했습니다.

## 리허설 체크리스트

각 질문을 **웹 UI에서 정확히 같은 문구로 3회**.

통과 기준:

- [ ] `route` / `분석 계획`이 **Planner** 경로로 보임
- [ ] fallback(PandasAI 등)으로 안 넘어감
- [ ] 결과 테이블이 납득 가능 (예산: 비목/집행률 상위, 매출: 상품 상위 5)

| 질문 | 1회 | 2회 | 3회 | 비고 |
|------|-----|-----|-----|------|
| Q1 비목별 실행예산 합계 | ☐ | ☐ | ☐ | |
| Q2 집행률 상위 3개 ⭐ | ☐ | ☐ | ☐ | |
| Q3 매출 상위 5개 상품 | ☐ | ☐ | ☐ | |

실패하거나 Plan이 왔다 갔다 하면 (본선 교체 후보):

| 용도 | 문구 | 비고 |
|------|------|------|
| 예산 예비 A | `실행예산 대비 집행률을 계산해줘` | 비율만, 벤치 최근 성공 |
| 예산 예비 B | `평균 집행률보다 높은 항목을 찾아줘` | 벤치 최근 성공 |
| Sales 예비 | `상품별 매출 합계를 알려줘` | 더 단순 |

Inventory는 최근 overall ~80%대라 **시연 2순위**로만.

자유 문구(`실행예산 대비 집행률이 높은 비목을 알려줘` 등)는 **오늘 3회 연속 성공**할 때만 본선 교체.
